# OpenCode 语音输入（全局长按说话）

在**任意软件**的输入框里**按住触发键（默认回车）说话，松开自动转写并粘贴**；短按触发键行为完全不变。
支持 OpenCode 以**管理员身份**运行（热键助手通过计划任务以最高权限启动）。

- 语音识别：**Qwen3-ASR-1.7B** 本地 GPU 推理（中文 / 中英混说 / 标点，离线）
- 触发键：**回车键**（默认）或**鼠标侧键**，长按判定，短按原样转发
- 临时关闭：**Ctrl+Alt+M** 一键暂停/恢复（暂停后所有按键恢复原生行为）
- 设置面板：托盘 H 图标右键 → **设置…**（触发键、阈值、最长录音、分段时长、暂停快捷键、生效范围、悬浮窗）
- 常驻服务：`voice_server.py`（预加载模型 + 环形缓冲 + 分段增量识别，实时字幕悬浮窗）
- 插件外壳：V2 CLI 插件（`/voice`、`/voice-status`、`/voice-setup` + 底部状态栏），供终端 TUI 使用

## 安装

### 方式一：安装包（推荐，分发给其他电脑）

从 `dist/OpenCodeVoice-Setup-<版本>.zip` 解压后**双击 `安装.cmd`**，会自动请求管理员权限并按步骤安装：

1. 准备 Python 3.12 环境与依赖（PyTorch CUDA + qwen-asr，约 2.6GB）
2. **自动下载离线语音模型 Qwen3-ASR-1.7B（约 4.7GB，带进度）** —— 安装包本身不含模型
3. 下载 AutoHotkey v2、部署 OpenCode 插件、生成本机配置与托盘图标
4. 可选创建计划任务（开机自启 + 兼容以管理员运行的程序）
5. 启动服务并自检，完成后即可使用

打包命令（开发者）：

```powershell
powershell -ExecutionPolicy Bypass -File build-package.ps1
```

### 方式二：源码目录直接安装

```powershell
# 普通权限运行即可；创建计划任务时会弹出一次 UAC 授权
powershell -ExecutionPolicy Bypass -File install.ps1
```

可选参数：

| 参数 | 说明 |
| --- | --- |
| `-InstallDir <路径>` | 安装目录，默认 `%USERPROFILE%\.config\opencode\voice` |
| `-Port <端口>` | 服务端口，默认 17860 |
| `-Model <模型ID>` | 默认 `Qwen/Qwen3-ASR-1.7B` |
| `-SkipModel` | 跳过模型下载（已有模型时） |
| `-NoTasks` | 不创建计划任务，改用启动文件夹快捷方式（普通权限） |
| `-NoStart` | 安装完不立即启动 |

安装器会：复制程序 → 建 Python 3.12 环境 → 装 PyTorch(CUDA)+qwen-asr → 下载模型（约 4.7GB）
→ 下载 AutoHotkey → 部署插件 → 创建两个计划任务 → 启动并自检。

## 使用

| 操作 | 效果 |
| --- | --- |
| 任意软件里短按触发键（默认回车） | 原样转发，行为完全不变（回车照常换行/发送） |
| `Shift/Ctrl/Alt + 回车` | 原样转发（`Shift+Enter` 换行不受影响） |
| 按住触发键 > 0.35s | 🎤 录音中，输入框上方出现实时字幕悬浮窗；松开后文字粘贴进当前输入框 |
| `Ctrl+Alt+M` | 暂停/恢复语音输入（暂停后触发键完全恢复原生行为） |
| `F8` | 备用开关：按一次开始，再按一次结束 |
| 鼠标侧键（切到该模式后） | 短按原样转发（浏览器前进等仍可用），长按触发语音输入 |
| 托盘 H 图标右键 | 语音输入开关 / 触发键 / **设置…** / 打开日志 / 重载配置 / 重载脚本 / 以管理员身份重启 / 退出 |

### 设置界面（托盘 → 设置…（推荐））

设置界面是**网页版**（HTML/CSS 实现，Apple 极简风格：卡片布局、iOS 风格开关、圆角与留白），由本地服务提供，用 Edge 的"应用窗口"模式打开，看起来就是一个原生设置面板：

- 顶栏右上角切换**外观**：自动（跟随系统）/ 浅色 / 深色
- **修改即自动保存**并立即生效（助手监听配置文件变化，约 2 秒内应用），无需点保存、无需重启服务
- 底部实时状态：服务 / 麦克风 / 权限 / 触发键 / 分段进度 / 预览耗时

| 分区 | 设置项 | 选项/范围 |
| --- | --- | --- |
| 触发与开关 | 触发键 | 回车键 / 鼠标侧键 |
| | 长按阈值 | 200~800 ms（滑块，默认 350） |
| | 临时关闭快捷键 | 点击后直接按组合键捕获，默认 Ctrl+Alt+M |
| | 当前启用语音输入 | iOS 风格开关（等同 Ctrl+Alt+M） |
| 录音 | 最长录音 | 5~600 秒（默认 60，到点自动结束） |
| | 分段时长 | 1~10 秒（默认 5，越小实时字幕越跟手） |
| | 麦克风 | 下拉枚举（带"刷新"） |
| | 识别语言 | 自动识别 / 中文 / English |
| 注入与范围 | 生效范围 | 所有窗口 / 仅 OpenCode / 自定义（填 `ahk_exe notepad.exe\|…`） |
| | 粘贴后自动回车发送 / 恢复原剪贴板 | 开关 |
| 悬浮窗 | 显示实时字幕 / 距窗口底部 / 最多显示 / 刷新间隔 | 开关 + 数值 |
| | 预览悬浮窗 | 按钮，直接看效果 |

托盘菜单里另有 **经典设置窗口**（旧的原生窗口），仅在打不开网页版时作为回退。


终端 TUI 里还可用：

- `/voice` 开始或停止录音，停止后把文字复制到剪贴板（Ctrl+V 粘贴）
- `/voice-status` 查看服务、麦克风、语言、阈值、最长录音、分段时长
- `/voice-setup` 选择麦克风、长按阈值、最长录音、分段时长

## 计算设备切换（GPU / CPU）

设置界面「性能 → 计算设备」可选：**自动（推荐）/ 显卡（CUDA）/ 处理器（CPU）**。

- 切到 **CPU** 时：服务会**重启**（进程级切换），新进程完全不初始化 CUDA → **显存占用归零**；同时**自动关闭实时预览**（省 CPU）
- 切回 **显卡** 时：服务重启并重新加载模型（约 8 秒），实时预览恢复
- 切换过程约 10 秒，界面会显示"正在切换…"；录音进行中不允许切换

### 实测性能（你的机器：i5-13600KF / RTX 4070 Ti SUPER）

| 项目 | 显卡（CUDA） | 处理器（CPU） |
| --- | --- | --- |
| 模型加载 | ~8s | **4.0s** |
| 1.0s 音频 | 0.34s | 0.88s |
| 2.0s 音频 | 0.42s | 1.22s |
| 4.2s 音频 | 0.53s | **2.1s** |
| 显存占用 | 约 3.5GB | **0** |
| 实时预览 | 支持（延迟约 0.7s） | 关闭（CPU 跑预览会占满核心） |

结论：CPU 约为显卡的 1/4~1/5 速度，**单句最终转写 1~2.5 秒仍可用**，适合"要腾出显卡玩游戏/渲染"的场景。

## 配置

`voice.config.ini`（改完：服务用 `voicectl.cmd restart`；助手在托盘菜单点"重载配置"）

```ini
[ui]
theme=auto          ; 外观：auto（跟随系统）/ light / dark

[voice]
port=17860          ; 服务端口
device=             ; 麦克风：留空=系统默认，或设备序号/名称片段
language=           ; 留空=自动，或 Chinese / English
preroll_ms=500      ; 长按前多保留的音频，避免吞字
model_dir=          ; 留空=同目录 models\Qwen3-ASR-1.7B
max_record_seconds=60     ; 单次录音上限（到点自动结束并粘贴）
partial_enabled=1         ; 实时预览开关
partial_interval_ms=280   ; 预览刷新间隔（毫秒）
partial_min_growth_ms=150 ; 新增音频超过多少毫秒才重新识别
partial_min_first_ms=300  ; 首次出现预览文字所需的最短音频
segment_seconds=5         ; 段落长度（秒）：定稿后不再重复识别
segment_overlap_ms=600    ; 段落重叠（毫秒），用于拼接去重

[overlay]
enabled=1           ; 实时字幕悬浮窗
offset_y=120        ; 距目标窗口底部的像素（越大越靠上）
max_chars=200       ; 最多显示多少字（超出显示末尾）
poll_ms=150         ; 悬浮窗刷新间隔（毫秒）

[hotkey]
trigger=enter       ; 触发键：enter（回车键）或 xbutton2（鼠标侧键）
hold_ms=350         ; 长按阈值（毫秒）
disable_hotkey=^!m  ; 临时关闭/恢复语音输入的快捷键
inject=paste        ; 注入方式：paste（剪贴板 + Ctrl+V）
auto_submit=0       ; 1=粘贴后自动回车发送
restore_clipboard=1 ; 1=粘贴后恢复原剪贴板
targets=*           ; 生效窗口：* = 所有窗口；也可 ahk_exe OpenCode.exe，多个用 | 分隔

[tasks]
server_task=OpenCodeVoiceServer
hotkey_task=OpenCodeVoiceHotkey
```

## 实时字幕（分段增量识别）

录音期间的准实时预览采用**分段增量识别**：

- 每 `segment_seconds` 秒把当前段落"定稿"并提交到前缀，之后**不再重复识别**（长语音单次耗时恒定）
- 预览只识别"当前段 + 重叠"，显示内容 = **已提交前缀 + 当前段**
- 松开回车后最终文本 = 已提交前缀 + 最后一段，因此 60 秒长语音的最终延迟也只有一次段落识别的时间
- 达到 `max_record_seconds` 自动结束并在悬浮窗提示

### 实测性能（20 秒连续语音，RTX 4070 Ti SUPER）

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 预览延迟（中位） | 1372ms | **692ms** |
| 预览延迟（平均） | 2407ms | **699ms** |
| 预览延迟（峰值） | 8000ms | **1196ms** |
| 单次预览耗时（中位） | 796ms | **458ms** |
| 60 秒长语音最终延迟 | ~4.0s | **~0.5s** |

模型单次耗时约 `0.25s 固定 + 0.062s/秒音频`，所以预览延迟的下限由段落长度决定。不同配置实测：

| segment_seconds / overlap | 预览延迟中位 |
| --- | --- |
| 2s / 400ms | 757ms（更差：定稿太频繁） |
| 3s / 400ms | 691ms |
| 4s / 500ms | 686ms |
| **5s / 600ms（默认）** | **692ms** |

想再快可把 `partial_interval_ms` 调到 150、`segment_seconds` 调到 4；想更省 GPU 则调大段落。

## 管理员权限说明

- 热键助手由计划任务 `OpenCodeVoiceHotkey` 以**最高权限**启动：无论 OpenCode 是否管理员，都能捕获按键并注入文本
- 转写服务由计划任务 `OpenCodeVoiceServer` 以**普通权限**启动：localhost HTTP 通信不受权限级别限制
- 助手启动时会检测目标窗口权限；若自身权限不足会给出提示（可用托盘菜单"以管理员身份重启"）

## 稳定性设计（自动恢复）

| 机制 | 说明 |
| --- | --- |
| 采集看门狗 | 服务每 5 秒检查音频帧；连续约 10 秒没有新数据就自动重开麦克风（带 20 秒超时保护，失败指数退避） |
| 进程自愈 | 连续 5 次恢复失败会退出进程（exit code 3），由计划任务的"失败自动重启"或助手的服务监控拉起 |
| 服务监控 | 助手每 20 秒检查一次服务，掉线自动拉起（安静模式，不打扰） |
| 转写重试 | 单次转写失败自动重试一次，错误写入 `/health` 的 `last_error` |
| 端口占用 | 明确记录日志并干净退出，不进入崩溃循环 |
| 悬浮窗提示 | 录音中若服务无响应 → "⚠ 语音服务无响应"；2.5 秒仍无音频 → "⚠ 麦克风没有声音" |
| 计划任务 | 两个任务都配置了失败自动重启（最多 5 次，间隔 30 秒） |

## 自检

一条命令检查全链路：

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\.config\opencode\voice\selftest.ps1"
```

会逐项检查：文件完整性、服务健康（含音频数据流）、麦克风枚举、**转写链路**（注入样例音频验证）、实时预览接口、助手进程、计划任务、插件部署，最后给出 通过/失败/警告 汇总。

## 排错

| 现象 | 处理 |
| --- | --- |
| 长按没反应 | 先跑 `selftest.ps1`；确认托盘有绿色 H 图标 |
| 悬浮窗显示"⚠ 麦克风没有声音" | 麦克风没采到数据：检查设备/静音开关，或 `voicectl.cmd restart`（看门狗通常会自动恢复） |
| 悬浮窗显示"⚠ 语音服务无响应" | 服务掉线，助手会自动拉起；也可 `voicectl.cmd start` 手动启动 |
| 提示权限不足 | 用计划任务启动助手，或托盘菜单"以管理员身份重启" |
| 中文输入法下确认候选词迟钝 | 回车被拦截后转发，若影响使用可改用 F8 |
| 转写不准 | 换更好的麦克风；或在配置里固定 `language=Chinese` |
| 想临时关掉 | 托盘菜单 → 退出；或删掉计划任务/启动快捷方式 |

### 1.3.0 — 2026-09-23

- **新增「计算设备」开关**（设置界面 → 性能）：自动 / 显卡（CUDA）/ 处理器（CPU）
- **切到 CPU 时显存完全释放**：采用**进程级切换**（服务自重启），新进程不初始化 CUDA，显存占用归零；仅清缓存的方式仍会残留 200~400MB 上下文，故不采用
- **CPU 模式自动关闭实时预览**（省 CPU），切回显卡时自动恢复
- 切换过程约 10 秒，设置界面显示"正在切换…"并在就绪后提示；录音进行中禁止切换
- 服务新增：`/device.txt`（当前设备）、`/health` 增加 `device_kind` 与 `compute`；`bench.py` 支持 `--device cpu|cuda`
- 助手：模型加载中（503）提示"正在加载模型，请稍候"；CPU 模式悬浮窗显示"（CPU 模式）"
- 配置版本升级到 v5（新增 `voice.compute`），安装器自动迁移

### 1.2.2 — 2026-09-22

- **修复悬浮窗文字堆叠**：实时字幕控件原先用了透明背景（`BackgroundTrans`），改文字时不会擦除旧内容，导致"预览 ↔ 转写中"切换时新旧文字叠在一起。现改为不透明背景，并在"长文本→短文本"时先清空再写入，同时做防御性重绘
- 悬浮窗文字区高度略增（容纳更多换行），排版更稳定

### 1.2.1 — 2026-09-22

- **修复"悬浮窗显示识别中但没有反应"**，从四个方向根治：
  1. **麦克风电平诊断**：服务实时上报输入电平（`/health` 的 `input_db`、`/level.txt`），悬浮窗在电平过低时直接提示"⚠ 麦克风声音太小（-52 dBFS）请调高输入音量"；未识别到语音时也会提示具体电平
  2. **松开事件丢失自愈**：录音未结束时，任何一次触发键按下都会立即收尾（不再开始新录音）；另加上限+15 秒的强制收尾兜底
  3. **预览线程看门狗**：录音中若预览线程意外停止，服务在助手轮询时自动重启它
  4. **静音保护可调**：阈值改为可配置（`silence_rms_x10000`，默认 -56 dBFS），并在日志中记录跳过原因与电平，便于定位
- 自检新增"输入电平可读"检查，电平过低时给出提示
